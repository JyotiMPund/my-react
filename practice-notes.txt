8)What is React router:
-React router is a standard library for routing in react application .
-it enables navigation between views(pages) of different components, 
-allowing you to build single page applications with multiple pages or routes -without fullpage reload

*Explain types of routing ->server side routing and client side routing:
->what is routing:
-Routing means showing different pages like(/home,/about,/profile) in your app or website.

a)Server side routing:-
->How it works:
    -Every time you click a link, browser sends request to a server.
    -The server responds with a new HTML page
    -The whole page reloads

Ex:You click /about → browser asks server → server sends HTML for "About" page.

->Used in:
    -Traditional websites like PHP, Django, Ruby on Rails
    -Slower, but great for SEO (search engines can read it easily).

b)Client side routing:
->How it works:-
    -The app loads once(usualy at /),then uses javascript to show/hide pages.
    -clicking the link doesn't reloads the page
    -React changes view instantly using components.
Ex:You click /about->no request to server->React shows "About" component

->used in:
    react,angular,vue apps
 -Faster, but needs extra setup for SEO or deep linking.

11)Difference between Functional component and class component:

*Functional Components:-
-Simple JavaScript functions
-Use hooks like useState, useEffect for state and lifecycle
-Do not use this keyword
-Easier to write, read, and test
-Preferred in modern React development
-Better performance in some cases (lighter components)
-Supports cleaner logic using custom hooks

* Class Components
-Use ES6 class syntax (class MyComponent extends React.Component)
-Manage state using this.state and update it with this.setState()
-Use lifecycle methods like:
-componentDidMount()
-componentDidUpdate()
-componentWillUnmount()
-Require using this keyword (e.g., this.state, this.props)
-More boilerplate code
-Hooks cannot be used inside class components
-Common in older React codebases

18)What is async/await?:
-async and await are javascript keywords used together to make it easier
to work with promise(whitch are used for Asynchronous operations like API calls,timers or reading files)

-they help you write Asynchronous code whitch looks like Synchronous code,make it easier to read,understand,debug

a)async keyword:-
-Makes a function always return a promise, no matter what.
-Allows you to use wait inside that function.

Ex:
async function SayHello(){
  return "Hello"
}

SayHello().then((msg)=>console.log(msg))

-Even though we return a string ,because the function is async ,it automaticaly return promise.

b)await keyword:-
-Can only be used inside an async function.
-It tells javascript to wait until a promise resolved or rejected before moving to the next line

Ex:
async function fetchData(){
  const response=await fetch("https://jsonplaceholder.typicode.com/users")
  const data=await response.json()
  console.log(data) // this runs after the data is fully received and parsed
}

Here’s what happens:
-The function pauses at await fetch(...) until the data compress
-then it pauses at await response.json to parse the data.
-then it logs the result
